    Console commands¶

    Every command the application adds to the console is prefixed beffroi:, and those that act on identity act on the tenant the configuration names. A command that reads is never the command that writes: beffroi:user:show reads, beffroi:user:profile writes, and they are two classes.

    Run bin/console beffroi:<group>:<command> --help for the arguments and the options of one of them; the table below is the map.

    The deployment and the tenant¶

    Command What it does
    beffroi:doctor Say whether this deployment holds together: one line per point looked at, and what to do about the ones it does not answer for. Reads and writes nothing, so it is safe on a provider serving traffic, and it fails when a point is red so a deployment pipeline can ask the question too.
    beffroi:statistics Say what the instance knows of itself now: its people, clients and open sessions, its keys by state, its acts by name over what the journal keeps, and the messages waiting in each lane. Reads and writes nothing.
    beffroi:tenant:login-floor Name the floor of every login of the tenant, and forget the credentials it forbids.
    beffroi:tenant:synchronize Write the row of the tenant of the configuration: created, renamed, or left alone.

    What beffroi:doctor looks at is what is wired, one class per point, so a point added to the application is a class added. It looks at every one of them before it answers: a doctor that stops on the first thing that is broken never reaches the second.

    beffroi:tenant:login-floor takes the name of a predicate, single_factor, two_factors, phishing_resistant or phishing_resistant_hardware, and writes it on the row of the tenant rather than in a file, since hardening a tenant is an act with a date. It asks before it runs, because every credential the floor reads nothing of is forgotten, its secret and its row: under phishing_resistant, the passwords, the one-time codes and the backup codes of every person go. Lowering the floor afterwards gives nobody back what was forgotten. The floor of its logins says what it changes.

    The chains of records and the database¶

    Command What it does
    beffroi:chain:sign-anew Link and sign one chain of the tenant again as the database holds it, once a person has read what its check found. Says what the check finds first, asks for the slug to be typed back, and writes the act to the journal.
    beffroi:chain:verify Walk each chain of the tenant whole against its signature, or one chain against a copy of a signed head kept outside the instance, and name the first position that does not follow. Reads and writes nothing.
    beffroi:database:grant Grant the role the processes run as what they serve, and no update nor deletion of the chained records but through the retention. Run as the role that owns the tables, after the migrations; the image does it when BEFFROI_MIGRATIONS_DATABASE_URL names that role.

    A chain is named journal, claim_history or disclosures, and beffroi:chain:verify walks the three when it names none; --against takes a file holding a signed head of the chain named, as the log channel chain printed it. beffroi:chain:sign-anew takes the chain, then the slug of the tenant typed back, and is run as the role that owns the tables, refusing under a role that may not delete a link; beffroi:database:grant takes the role of PostgreSQL the server and the worker connect as. The chains of records says when to run each.

    Users, their credentials and what they agreed to¶

    Command What it does
    beffroi:user:applications List the applications a user agreed to, with what each one holds of them and what it has asked that is still waiting.
    beffroi:user:create Create a user of the tenant; give them a password with beffroi:user:set-password.
    beffroi:user:disable Disable a person: they can no longer sign in, and every session of theirs ends, its applications told by back-channel logout. To let them sign in again, see beffroi:user:enable.
    beffroi:user:enable Enable a person beffroi:user:disable disabled: they may sign in again, every session of theirs having ended with the disabling.
    beffroi:user:enrolment-ticket Issue the link that lets a person pose a passkey, and print it.
    beffroi:user:journal List the acts of a user over a period, with the application each one was done on behalf of and the administrator who did one to them; for answering a request about what happened in their name.
    beffroi:user:link Say that a user of the tenant is a given subject at an upstream provider; run again to refresh it.
    beffroi:user:password-ticket Issue the link that lets a person pose a new password without the one in use, and print it; spending it ends every session of theirs.
    beffroi:user:profile Describe a user with the standard claims of OIDC Core section 5.1; what is not said is cleared, except what the upstream provider that created the user holds, which is kept, and saying that otherwise is refused; a run that says nothing writes nothing. To read a user, see beffroi:user:show.
    beffroi:user:reindex Derive again the blind indexes of every person of the tenant, after the projection of one changed.
    beffroi:user:revoke-consent Take back the consent a user gave a client, and the access it holds; the next authorization request asks again.
    beffroi:user:revoke-credential Revoke a credential of a user by its identifier; the credential stays listed as revoked.
    beffroi:user:revoke-session End a session of a user by its identifier; the relying parties of that session are told by the back-channel.
    beffroi:user:sessions List the sessions open in the name of a user, with what each one proved and where it was last seen.
    beffroi:user:set-password Set or replace the password of a user, asked on the terminal or read from the standard input.
    beffroi:user:show Show a user: the identity with the source that created it, the standard claims that are set, the credentials with their kind, identifier, name, authenticator, what their enrolment proved of it and dates, and the groups with the source of each membership.
    beffroi:user:totp-ticket Issue the link that lets a person set up an authenticator app in place of the one they hold, and print it; spending it ends every session of theirs.

    A ticket is a link that lets one person act once on their account without a session: pose a passkey, beffroi:user:enrolment-ticket; pose a new password without the one in use, beffroi:user:password-ticket; or set up an authenticator application in place of the one they hold, beffroi:user:totp-ticket. It opens once, for seventy-two hours, and it is printed once: the row holds a hash of what it carries. Issuing another of the same kind for the same person takes the first one away, and a disabled account gets none. A password or an authenticator application ticket is refused where the floor of the tenant or the domain of the person admits no such credential. A ticket proves no login, and spending a password or an authenticator application ticket ends every session of the person.

    Disabling a person ends every session of theirs, and enabling them again gives nothing back: a disabled user says where they are refused.

    The journal of a person is read over --from and --to, two days in UTC, both included, narrowed with --act, repeatable, and --client, and written as a table or, with --format=json, as the document a request under article 15 of the GDPR is answered with. A period that reaches past what the deployment keeps is answered with how long it keeps an act and the day that reaches, never with an empty table that looks complete.

    Groups¶

    Command What it does
    beffroi:group:add-member Make a user a member of a group of the tenant, a membership the tenant holds itself.
    beffroi:group:create Create a group of the tenant, which the declaration of an upstream provider may map the groups it asserts to.
    beffroi:group:remove-member Take a user out of a group of the tenant, a membership the tenant holds itself.

    No upstream provider creates a group: the declaration of one maps the values it asserts to groups that exist already, by their name, and a value naming a group the tenant does not hold is no group. beffroi:group:add-member and beffroi:group:remove-member take the name of the group, exactly as the tenant holds it, then the username, and take back no membership a provider or a directory gave. A person added to or taken out of a group tenant.administrators names starts or stops administering the tenant at once.

    Clients and initial access tokens¶

    Command What it does
    beffroi:client:delete Delete a client that registered itself; a client declared in the configuration is refused.
    beffroi:client:list List the clients of the tenant: where each came from, when it was registered and when it was last used.
    beffroi:client:show Show a client of the tenant: where it came from, its dates, and what it registered.
    beffroi:client:token:issue Issue an initial access token for the tenant, and what it gives the clients it registers; the value is printed once and never again.
    beffroi:client:token:list List the initial access tokens of the tenant: what each has served, what it has left and whether it still authorises anything.
    beffroi:client:token:revoke Revoke an initial access token by its identifier; it authorises no registration from that instant.

    Signing keys¶

    Command What it does
    beffroi:keys:activate Make a staged key the active one of its algorithm before its staging delay elapsed; the key it takes over from starts retiring.
    beffroi:keys:generate Generate a key, seal it with the configured KMS and make it the active one of its algorithm at once; "beffroi:keys:rotate" is the rotation without an outage.
    beffroi:keys:list List the keys of the tenant with their use, status and dates: the published ones, or every key with --all; --check opens the keys in use, or about to be, with the KMS and fails on one it cannot open, or that has worked past its age with nothing staged behind it.
    beffroi:keys:retire Take a retiring key out of the JWK Set: one key by its identifier, before its retirement date with --force; or every key past its date with --due.
    beffroi:keys:rotate Stage a new key, sealed by the configured KMS and published at once; it takes over once the staging delay elapsed, or at once with --now; --compromised retires the previous key, and every other key of its algorithm, with no window.

    --algorithm names the key a command acts on: a JWS algorithm for a key that signs tokens, a JWE key management algorithm for a key clients encrypt to, or one of the keys the tenant keeps rather than publishing, among them SAML-SIGNING, the key both SAML roles sign with, and SAML-ENCRYPTION: followed by the entity ID of an upstream identity provider, the key that provider encrypts for. Left out, it is the default signature algorithm.

    Data keys¶

    Command What it does
    beffroi:data-keys:destroy Erase the data keys of the tenant, which makes every personal datum it had sealed unreadable for good. Asks for the slug to be typed back. Cannot be undone.
    beffroi:data-keys:list List the data keys of the tenant by scope, with when each was minted, the master key that wraps it and the KMS client that opens it; reads only, and never opens a key.
    beffroi:data-keys:rewrap Wrap the data keys of the tenant with another KMS client from now on, or with another master key of the same one; --dry-run lists what would move. No sealed value is read or rewritten.

    Addresses¶

    Command What it does
    beffroi:geoip:refresh Download the GeoLite2 databases of addresses now, refuse what is not one, and store them for the enrichment of a provenance; --url for a mirror or a file already unpacked.

    A timed step runs the same object once a week, which is the cadence the databases are published at, so the command is for installing them the day a deployment subscribes and for reading why a refresh was refused. A deployment that names no licence key downloads nothing and serves every flow with a provenance that says an address and no place. A download, the database unpacked from it, or what the archive holds besides it, larger than 512 MiB is refused, and nothing of it is kept.

    SAML metadata¶

    Command What it does
    beffroi:saml:service-provider:refresh Read the metadata of the service providers the configuration declares, or of one of them, and keep each document accepted; an expired or an older document is refused and the one accepted kept.
    beffroi:saml:service-provider:forget Forget the metadata accepted for a service provider, so that the next refresh registers it again as a first one; the refresh refuses older documents only against what is accepted.
    beffroi:saml:identity-provider:refresh Read the metadata of the upstream identity providers the configuration declares, or of one of them, and keep each document accepted; an expired or an older document is refused and the one accepted kept.
    beffroi:saml:identity-provider:forget Forget the metadata accepted for an upstream identity provider, so that the next refresh registers it again as a first one; the refresh refuses older documents only against what is accepted.
    beffroi:saml:identity-provider:list List the upstream identity providers the configuration declares, each with the URL of the metadata of the service provider to hand it.

    A timed step runs the same refresh every hour for the peers of both roles, so the command is for the first reading of a peer just declared and for reading why a document was refused. Forgetting is never a step of the schedule: it is the one way back from a signed document an operator decides to stop holding the provider to.

    beffroi:saml:identity-provider:list reads the declarations and writes nothing. The URL it gives is the one the router writes under the origin of the issuer, its last segment the entity ID of the provider in base64url, and it answers once the tenant holds a key in service for that provider, which beffroi:keys:generate --algorithm=SAML-ENCRYPTION:<entity ID> draws. A tenant that declares no identity provider is told so, and the command fails.

    Passkeys and FIDO metadata¶

    Command What it does
    beffroi:webauthn:aaguids-refresh Download the list of passkey providers the community keeps (names and logos by AAGUID, unsigned), refuse it unless it is that list and names one, and store it for the pages that name the authenticator of a passkey; --url for a mirror.
    beffroi:webauthn:mds-import Store a metadata statement file (unsigned, trusted as the file is) next to the FIDO Metadata BLOB, for the keys of a manufacturer the service does not list or the authenticators of the FIDO conformance tools.
    beffroi:webauthn:mds-refresh Download the FIDO Metadata BLOB, verify its signature under the pinned root and store it for the passkey ceremonies; --url for another service, --root for another root.

    Nothing runs these three on its own. The model of the authenticator of a passkey, which the page of the passkeys and beffroi:user:show name, is read from the FIDO metadata first and then from the list of the community, the aaguid.json of passkeydeveloper/passkey-authenticator-aaguids. That list is signed by nobody and carries no licence, so the image ships none of it: a deployment that never ran beffroi:webauthn:aaguids-refresh names an authenticator from the FIDO metadata alone. A list refused, an empty one or a download the service redirected among them, keeps nothing and leaves the stored one as it was.

    What a command may not do¶

    A command never bypasses a rule the protocol applies. It cannot mint a token for a user, cannot read a signing key it is not allowed to open, and cannot read a personal datum the key management service refuses to unseal.

    Four commands cannot be undone. beffroi:data-keys:destroy asks for the slug of the tenant to be typed back before it runs, beffroi:tenant:login-floor asks before it forgets the credentials the floor leaves out, beffroi:client:delete deletes a client that registered itself, and beffroi:chain:sign-anew asks for the slug as well before it links a chain again, after which what was changed in it before cannot be told from the rest.
